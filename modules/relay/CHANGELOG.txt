relay Router App - Changelog
============================

1.2.0
-----
* Register /opt/relay/etc/settings with Cumulocity configuration management, so
  MOD_RELAY_* can be edited from the cloud (Device Management > Configuration).
* relay-agent now watches the settings file and reloads (re-exec) when it
  changes, so a cloud configuration update is applied without a manual restart.

1.1.0
-----
* Fix the Cumulocity operation wiring to match how thin-edge.io delivers the
  built-in relay operations:
  - c8y_Relay is handled as a JSON operation (on_fragment = c8y_Relay), with the
    relayState (OPEN/CLOSED) substituted into the command by the mapper.
  - Add c8y_RelayArray for the Cumulocity RelayArray widget: the desired array
    is parsed and this device drives the element at $MOD_RELAY_OUTPUT.
* relay-control now understands the Cumulocity OPEN/CLOSED values (CLOSED =
  relay energised), in addition to on/off aliases.
* Reflect the new relay state into the device managed object (c8y_Relay /
  c8y_RelayArray twin fragments) so the relay widgets update.

1.0.0
-----
* Initial release. thin-edge.io extension that controls a router digital output.
* relay-agent: subscribes to the local MQTT topic relay/<id>/set (Pattern A).
* c8y_Relay: Cumulocity custom operation registered with the tedge mapper,
  handled by relay-c8y-op (Pattern B).
* relay-control: the single hardware-specific script (adapt to the ICR-1642 I/O).
* Built for ICR platforms v2i / v3 / v4 / v4i (ICR-1642 == v4i).
