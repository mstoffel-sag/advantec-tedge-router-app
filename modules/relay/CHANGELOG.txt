relay Router App - Changelog
============================

1.0.2
-----
* Fix: actually drive the relay output. relay-control detected the ICR-OS `io`
  utility with `command -v io`, but the ICR-OS shell (abox) has no `command`
  builtin -- `command -v` fails with "command: not found", so detection always
  failed and the operation reported "no known relay interface for output 'out0'"
  even though /usr/bin/io is present. Detect `io` by its executable path instead
  (with a `type` fallback). Verified on an ICR-4400: c8y_Relay now drives out0
  (CLOSED -> io=1, OPEN -> io=0) and the operation completes successfully.

1.0.1
-----
* Fix: the c8y_Relay / c8y_RelayArray operation handlers now use
  topic = "c8y/devicecontrol/notifications" (was "c8y/s/ds"). The bundled
  thin-edge 2.0.1 flows mapper dispatches custom exec-operation (on_fragment)
  handlers only on the JSON operation topic; paired with c8y/s/ds the operations
  never reached the relay script. (Built-in mapper operations such as
  remote_access are unaffected -- they use a native dispatch path and work with
  the stock s/ds declaration.)
* Fix: etc/install and etc/uninstall now source /opt/tedge/env before calling
  the tedge CLI. thin-edge.io is relocated to /opt/tedge but the tedge binary's
  compiled-in default config dir is /etc/tedge; without the env, TEDGE_CONFIG_DIR
  is unset and `tedge reconnect c8y` read the absent /etc/tedge and silently
  failed, so the relay operations were never announced to Cumulocity after
  install (they would only appear after the next mapper restart).

1.0.0
-----
* Initial release. thin-edge.io extension that switches one or more of the
  router's digital outputs (relays) from Cumulocity IoT.
* Cumulocity operations:
    - c8y_Relay      single relay (relayState OPEN/CLOSED); drives the first
                     configured output.
    - c8y_RelayArray the Cumulocity RelayArray widget; drives every configured
                     output from its matching array position.
  The new state is reflected into the device managed object (c8y_Relay /
  c8y_RelayArray twin fragment) so the relay widgets update, and the initial
  state is seeded on start so the widget renders one toggle per output.
* Multiple outputs via MOD_RELAY_OUTPUTS (ordered list of ICR-OS `io` names):
  ICR-1642 has one output (out0); ICR-44xx has two (out0 out1); expansion-port
  outputs are supported by name.
* Cloud-only: relays are switched by Cumulocity operations (no local MQTT topic
  and no persistent daemon). Configuration changes apply on the next operation.
* Settings registered with Cumulocity configuration management, so the output
  list can be edited from the cloud (Device Management > Configuration).
* relay-control is the single hardware-specific script (ICR-OS `io` command).
* Built for ICR platforms v2i / v3 / v4 / v4i (ICR-1642 = v4i; ICR-44xx = v4).
